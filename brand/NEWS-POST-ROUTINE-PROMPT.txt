You are publishing **one** new regular Industry LoogoBlog post on loogolabs.com. It is
**not** the featured post: do not change which post is featured. Work in the
`jselvalugo/LoogoLabs-Official-Website` repository. Follow the steps in order.
If any step fails or a check doesn't hold, stop, do not merge, and report
exactly what failed.

### 1. Start clean

- `git fetch origin main`, then create `claude/news-post-YYYY-MM-DD` (today's
  date) from `origin/main`. If that branch or an open PR for it already exists,
  stop: one post per run.
- `npm ci` if `node_modules` is missing.

### 2. Read the house rules, in full, before writing anything

- `brand/CONTENT-POLICY.md`: originality is absolute.
- `brand/BLOG-VOICE.md`: voice, reader and byline (first person, as David Selva).
- `brand/GHL-CONTEXT.md`: what the platform does. Never name the platform or any vendor.
- `brand/BLOG-TOPIC-LOG.md`: every topic + vertical pairing already used.

Also skim the **titles, excerpts and first paragraphs** of the 10 newest posts in
`content/posts.mjs`, only to avoid repeating their angle, opening or closing.
Do not reuse their wording.

### 3. Pick the topic

- Choose a topic + vertical pairing that is **not** in `brand/BLOG-TOPIC-LOG.md`
  and doesn't make the same argument as an existing post in a different vertical.
- One specific, practical problem a local service business owner has, with a fix
  they can act on themselves.
- Before writing, state in one line each: the reader, the problem, the fix. If
  you can't fill all three crisply, pick another topic.

### 4. Write the post — original work only

Write it yourself, from a blank page. Do **not** search the web, open other
blogs or articles, or paste in any outside text as a reference or "context".
No copying, paraphrasing or restructuring someone else's piece, no quotes from
others, no borrowed lists or frameworks, and no statistics, studies or figures
you can't stand behind — if a number isn't from your own reasoning ("if you
book 20 jobs a week…"), leave it out. Examples must be invented and clearly
illustrative, never real named businesses or people.

Add one object at the **top** of the `posts` array in `content/posts.mjs`:

```js
{
  slug: `short-keyword-slug`,        // lowercase, hyphens, unique in the file
  title: `Title Under ~70 Characters`,
  excerpt: `One sentence that makes someone want to read it.`,
  tags: `Topic, Subtopic, Vertical`, // 2–3, comma-separated
  content: `Markdown body…`,
},
```

Requirements:

- **Excerpt**: shown on the post card in /news and in the RSS feed. One
  sentence, under ~200 characters, no surrounding quote marks, not copied from
  the body.
- **Title**: under ~70 characters, concrete, no clickbait.
- **Opening**: start on the problem, not a preamble or a question to the reader.
- **Body**: 450–900 words, `##` section headings, short paragraphs.
  Only `##`, `###`, `-` lists, `>` quotes, `**bold**`, `*italic*`, `` `code` ``.
  No links, images, tables or HTML.
- Escape every backtick in text as `` \` `` (the strings are template literals);
  avoid `${` in text.
- End with **one** concrete thing the reader can check or change this week.
- Do **not** add a `featured` field.

### 5. Generate the post migration

`npm run db:generate-post-migration -- new_post_<short_slug>`

Open the new `netlify/database/migrations/<stamp>_new_post_<short_slug>/migration.sql`
and confirm the new post is in it. The generator upserts every post; that's
expected — existing posts keep their `status` and `published_at`.

Do **not** run `npm run db:feature-post`. The current featured post stays featured.

### 6. Confirm nothing else changed

- `git diff origin/main -- content/posts.mjs` shows **only** your new object added.
- No new `*_feature_*` migration folder exists in your diff.
- Nothing in the diff edits, deletes or re-dates any existing post.

### 7. Log the topic

Append a row to `brand/BLOG-TOPIC-LOG.md`:
`- YYYY-MM-DD | <slug> | <vertical> | <topic>`

### 8. Check it — build, then two full review passes

Run the build first, then do **two separate review passes**. Do not merge
until both passes are complete and clean. If either pass changes the post,
re-run the build and repeat that pass.

**Build and mechanics**

- `npm run build` must pass (it also regenerates the sitemap, RSS feed and the
  pre-rendered post page). Confirm the new slug appears in the generated sitemap.
- Count the body words and confirm 450–900.
- Confirm only supported Markdown is used and every backtick is escaped.

**Review pass 1 — originality and copyright**

Read the whole post slowly, sentence by sentence, and ask of each one:

- Did I write this myself, or is it a phrase, slogan, tagline, headline or
  sentence I recognise from somewhere else? If you recognise it, rewrite it.
- Does any section follow the outline, list or framework of a known article,
  book, course or vendor guide? If so, restructure it in your own order.
- Is there any quotation, lyric, poem, brand slogan, trademarked method name or
  named person's idea? Remove it.
- Is there any statistic, percentage, study, survey or "research shows"? Remove
  it unless it is simple arithmetic you worked out in the post itself.
- Are the platform, any vendor, any real business or any real person named?
  Remove them.
- Is the title or excerpt identical or near-identical to an existing post on
  the site, or to a well-known article title? Change it.

Write a short note for the PR: "Originality pass 1: <what you changed, or
'no changes needed'>".

**Review pass 2 — fresh read for voice, accuracy and originality again**

Start again from the top as if you were a different editor seeing it for the
first time. Check it against `brand/CONTENT-POLICY.md` and `brand/BLOG-VOICE.md`:

- Repeat every originality and copyright check from pass 1. A second look
  catches what the first one missed.
- Is every claim practical and true for a typical local service business? Cut
  anything you can't stand behind.
- Does it sound like David Selva talking to one owner, in first person? Rewrite
  anything generic or machine-made: filler openers, "in today's world",
  "game-changer", "unlock", tidy rule-of-three lists, a closing paragraph that
  just repeats the post.
- Does it open on the problem and end with one concrete thing to do this week?
- Does it differ in angle, opening and closing from the 10 newest posts?

Write a short note for the PR: "Review pass 2: <what you changed, or 'no
changes needed'>". If you are not confident the post is fully original after
pass 2, stop, do not merge, and report why.

### 9. Ship it

- Commit: `Add Industry LoogoBlog post: <title>`
- Push the branch and open a PR against `main` with the same title. Body:
  - **Title**, **Excerpt**, **Slug**, **Tags**, **Word count**
  - **Originality pass 1** and **Review pass 2** notes from step 8
- Merge only once the checks pass **and** both review passes are recorded clean.
  Netlify deploys `main` and applies the migration; the post appears in the
  /news "All posts" grid and latest-posts lists by date.
- After deploy, if you can, load `/news` and the new post's URL and confirm it
  shows, and that the featured post is unchanged.

### Rules

- One post per run. If no unused pairing fits, stop and say so — never reuse one.
- Never change the featured post in this routine.
- Never edit, delete or re-date an existing post.
- Never hand-write or edit migration SQL; always use the npm script.
- Never publish anything copied, paraphrased or adapted from another source.
  Two review passes are required before every merge.
- Never touch page code, styles or other brand files in this routine.
